# SkillDock 用户指南

版本：1.0（2026-09-09）· 适用版本：SkillDock 0.1.0（P0 内部测试包）
一处维护，随处可用：把本地技能库同步到多个 AI 编程工具的技能目录。

---

## 1. 三分钟上手：首次同步

**第一步，选择技能库。** 打开应用 →「添加技能库」→ 选择包含技能文件夹的目录（或直接把文件夹拖进来）。应用会自动在根目录、`skills/`、`.agents/skills/`、`.claude/skills/`、`.codex/skills/` 中寻找技能集合：

- 只有一个候选时自动选定；有多个候选时请选择一个（不同集合不会合并）。
- 单个技能文件夹也可以添加：选择该文件夹本身，应用按「单个技能」登记。
- 列表里同时显示技能数量与问题数量；无效项（如 YAML 错误、名称与目录不一致）会标出原因和行号，只影响该项本身。

**第二步，选择同步工具。** 在「同步目标」页勾选工具：Codex、Claude Code、Cursor、GitHub Copilot（VS Code），或「添加自定义目录」。

- 卡片显示将写入的完整路径、路径来源（模板/环境变量/自定义）、目录是否可写。
- 目录不存在也可以先保存，首次执行时会创建。
- 同一真实目录被多个工具引用时，只算一个物理目标，只复制和备份一次。
- 提示「此位置也可能被 Cursor / Copilot 读取」时，说明该目录会被多个工具发现（兼容读取），这是正常现象。

**第三步，检查并同步。** 回到「技能库」，勾选技能（无效项默认不勾选）→「预览同步」→ 确认汇总后点「同步」。

- 预览按目标分组显示：新增、更新、冲突、跳过逐项可见，文件级变化（含将被删除的文件）都可展开。
- **预览只包含无冲突项**；冲突项必须处理后才纳入（见 §2）。
- 预览后如果源或目标内容有变化，旧计划会被拒绝执行并提示「内容已变化，请刷新预览」——这是保护机制，不是故障。

**快捷键**：`Ctrl+O` 添加技能库 · `Ctrl+F` 搜索 · `F5` 刷新 · `Ctrl+Enter` 打开同步预览 · `Esc` 关闭抽屉。

---

## 2. 冲突处理

当目标目录与应用记录不一致时，对应项显示为冲突（本地修改 / 双方修改 / 同名冲突 / 来源冲突），**默认保留目标内容，绝不静默覆盖**。打开冲突抽屉后可逐项选择：

| 选择 | 含义与后果 |
| --- | --- |
| **本次保留目标** | 这一项不同步，目标原样保留。下次预览仍会提示。 |
| **备份后用源覆盖** | 先把当前目标完整备份，再用源库内容覆盖。可从「同步历史」恢复。 |
| **接管现有目录** | 目标与源内容一致时出现：不复制文件，只建立托管记录（基线）。 |
| **接管并用源覆盖** | 目标是未被管理的同名不同内容目录时出现：先备份再覆盖，此后纳入托管。 |
| **始终暂停此映射** | 该「技能 × 目标」组合不再参与同步（显示「已暂停」），可随时恢复。 |

**批量处理**：预览的冲突区提供批量按钮，可把同一类冲突（如「已有相同内容、可接管」的项）一次性全部接管或全部保留。内容不同的项不会被批量覆盖误伤。

**提示**：多个技能库同步到同一目标时，同名技能只允许一个来源库拥有；如需更换来源，请在预览中明确「转移归属」。

## 3. 移除与「源已删除」

- 源库里删除整个技能后，**目标端默认保留**，状态显示「源已移除，目标保留」——应用不会自动删除你的目标目录。
- 想彻底移除某个托管技能：在技能详情或目标页进入「移除托管技能」预览（独立操作），确认后先备份再删除。
- 「取消勾选」只是停止后续同步，不删除磁盘上的任何文件。

## 4. 历史与恢复

「同步历史」记录每次任务：时间、来源库、目标、各类数量（成功/失败/跳过/待处理）、耗时与逐项结果。

**恢复某个历史版本**：

1. 打开任务详情，勾选要恢复的目标技能（可多选）→「预览恢复」。
2. 应用会展示「当前 → 历史版本」的变化；如果恢复点之后目标又有修改，会显示冲突，需要你确认后才覆盖。
3. 恢复前会自动给当前目标再做一个快照（可再反悔）；恢复成功后，相关映射会**暂停自动同步**（避免刚恢复的内容被立即盖掉），源库保持当前版本不变。想恢复常规同步，重新预览即可。

**关于备份**：

- 更新、覆盖、接管、移除、恢复之前都会先备份；备份失败的项不会被执行（目标保持原样）。
- 首次创建会记录「原先不存在」——恢复时可以撤销尚未被改动的首次创建。
- 快照默认保留 30 天、总量软上限 2 GiB；每个映射至少保留最近一次可用备份。过期的快照在历史中标记「备份已过期」，不再提供恢复（当前目标不受影响）。
- 备份容量可在「设置」中调整。

## 5. 操作日志（独立于数据库的永久记录）

每次任务完成（扫描/同步/移除/恢复）都会向 **`文档\SkillDock\SkillDock-操作日志.jsonl`** 追加一行 JSON 记录（时间、任务、状态、计数、逐项结果）。

- 这是给你看的长期可读记录，**重装应用、数据库损坏都不影响它**。
- 在「设置」页可点「打开日志目录」直接查看。
- 应用自身的配置与数据库在 `%LOCALAPPDATA%\com.skilldock.app\`，卸载默认保留（重装不丢配置和历史）。

## 6. 常见问题排查

### 「权限不足 / 拒绝访问」

先看错误详情里的路径，常见原因：

- **目标是符号链接或目录联接**：应用按规则不跟随、不改动链接（包括指向已不存在位置的悬空链接）。请在文件资源管理器中确认后手动删除该链接，再刷新预览。
- **文件被其他程序占用**：关闭正在使用这些文件的编辑器/工具后重试（错误可重试）。
- **目录无写权限**：换一个有写权限的位置，或调整文件夹权限后重试。应用日常运行不需要管理员权限。
- **OneDrive 等同步目录**：云占位文件未落盘时会被标记为不支持；请先把内容同步到本地，或改用本地目录。

### 技能显示「不支持」或「校验异常」

- 「不支持」：技能目录内含符号链接/目录联接，或元数据引用了技能目录之外的相对路径（`../`）——分发出去会不完整，因此被阻止。
- 「校验异常」：点详情看具体原因与行号——缺少 `name`/`description`、名称含大写或连续连字符、名称与目录名不一致、YAML 语法错误。修复源文件后按 F5 重新扫描。

### 提示「路径重叠 / 循环」

目标目录与技能库源根相同或互为父子、或两个目标根互相包含时会阻止保存——这会导致循环同步或自我覆盖。请把目标换到源库之外的目录。

### 任务失败或「待恢复」

- 单项失败不影响其他项：任务结果里可只重试失败项。
- 应用崩溃或中断后，下次启动会自动检查未完成事务：能确认成功的登记成功，否则恢复旧版本；发现无法识别的内容时**保留现场**并提示人工处理（不会覆盖未知内容）。
- 错误信息中的「诊断详情」可配合 `文档\SkillDock\SkillDock-操作日志.jsonl` 定位。

### 长路径或特殊字符

- 中文、空格、常见特殊字符的路径都支持。
- 完整路径超过约 240 字符时该项会被阻塞并建议缩短路径（Windows 传统路径长度限制）。

## 7. 隐私与边界

- 所有扫描、同步、恢复均在本机离线完成；无账号、无遥测、不上传任何技能内容。
- 应用只做「文件一致」：文件同步成功不代表 Agent 已加载或能运行（技能可能依赖特定运行环境）。如工具未显示新技能，请按该工具的说明刷新或开启新会话。
- 不管理企业策略目录、工具内置技能和插件缓存目录。
