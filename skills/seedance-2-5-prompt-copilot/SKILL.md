# Seedance 2.5 Prompt Copilot

将已批准的 Brief 和参考包转化为可控的 Seedance 2.5 提示词、完整时间码视听计划，以及审查/修复循环。

## 1. 强制性前置流程（Mandatory Preflight Form）

每次调用本技能，第一步必须向用户展示确认表单。获得明确提交前，禁止调研、规划、撰写提示词或生成。

表单 4 个必填项：

| 字段 | 说明 |
|------|------|
| Brief 确认 | 单选：确认并继续 / 需要修改。概括目标、受众、渠道、交付物 |
| 时长或范围 | 确认视频确切时长或非生成类输出范围 |
| 生成模式 | 单选：多参考模式（推荐）/ 首末帧模式。列出每个检测到的参考及其角色 |
| 验收标准与风险 | 确认主要可见成功标准和最高风险锁定项（身份、产品/SKU、几何、文案、对白、版权、证据、安全、本地化、披露、终态等） |

提交标签需本地化，例如「确认并继续」。只有真实的结构化提交才能授权继续；跳过、关闭、超时均不算批准。

## 2. 默认多参考模式

创意默认始终以多参考模式开始，不因附件数量自动切换。首末帧模式仅经表单明确确认后使用——它用两张有序图像锚定起始和终态，不是简化版多参考工作流。

写提示词前构建 **Reference Role Map**，为每个来源分配一个主要权威：

- 身份/产品/IP
- 场景/几何
- 故事板/镜头顺序
- 运动/表演/镜头
- 风格/材质/光线
- 对白/语音/音乐/节奏
- 源视频/剪辑范围
- 证据/文案

优先级：**P0** 违反即失败（身份、SKU、几何、精确文案、证据、端点、版权）；**P1** 指导运动、镜头、音频、故事板或材质；**P2** 氛围或可选润色。

## 3. 运行时边界

运行时（如 tapnow-cli）拥有当前模型 ID、模式、时长、分辨率、输入类型、参考上限、编辑控制、参数、价格、可用性、提交和结果状态。生成前必须：读取实时 Seedance 2.5 契约 → 解析所有已确认媒体 → 验证模式、包、时长和参数 → 提交最终提示词和参考顺序（不变更）→ 检查结果。

如果 2.5 不可用：交付已批准的提示词包并报告缺口，**不得静默回退到 2.0**。

## 4. 工作流程（8 步）

表单授权后：

1. 识别主要验收族别（参考编排；首末帧；故事/预演/表演；商业/增长；知识/企业/本地化；事实/监管；空间/移动/旅行；本地编辑/修复）
2. 按 `references/router.md` 仅从路由器加载所需参考
3. 构建 Reference Role Map、不可变锁定列表和冲突备注
4. 选定一个结果、因果事件序列、镜头和剪辑语法、音频层级、具体终态
5. 撰写覆盖确认时长的连续 Timeline
6. 按第 7 节模板组装最终提示词
7. 审查：参考影响、连续性、动作顺序、音频、真实性、版权、披露、交付格式
8. 修复：仅修复失败区域/片段/指令；保留通过的部分

参考路由详见 `references/router.md`；各参考条目详细内容见 `references/reference-details.md`。

## 5. 时间线控制（Timeline Control）

每个最终生成或视频编辑提示词必须包含可见 Timeline，使用精确格式 `【0:00-0:03】`。

规则：

- 从 0:00 开始，覆盖完整确认时长，无间隙、无重叠，精确结束于确认时长
- 每个区间给一个主导事件和结果态；包含镜头、转场或切换、同步音频/对白、相关保留锁定
- 按复杂度分配时间，而非均分；保留预期、接触、反应、恢复和可读的最终停留
- 将精确对白、歌词、UI 事件、声明、撞击、匹配剪辑和节拍提示放在其所属区间内
- 源视频编辑时，区分源时间码和输出区间并说明映射
- 较长序列使用更多区间，而非超载每个区间

规范模板：

```
Target duration: 15 seconds
Timeline:
【0:00-0:03】Hook and opening state; camera: one clear move; audio: first cue.
【0:03-0:08】Primary action and visible proof; preserve: identity, product, geometry.
【0:08-0:12】Reaction, escalation, or comparison; transition: motivated and timed.
【0:12-0:15】Payoff, exact CTA or final state, and readable hold.
```

## 6. 提示词规则

- 参考绑定先于创意描述：命名每张图像、视频、音频、故事板、脚本或模型控制什么
- 按时间顺序描述可见事件，每个动作给出一个结果
- 当交互或几何重要时，陈述主体/物体/镜头的空间关系
- 每个区间使用一个主要镜头意图；剪辑必须揭示新信息
- 保留精确用户对白、歌词、可见文案、标签和法律用语
- 分离对白、环境音、物理效果、画内音乐和观众专属配乐
- 使用白模参考保留已解决的空间/镜头/动作，同时改变表面和光线；使用绿幕参考隔离运动或表演转移
- 将故事板视为有序镜头逻辑，而非风格拼贴
- 事实或监管工作中，生成视觉仅用于说明已批准来源，不能作为证据
- 禁止将未经验证的提供商限制或不支持的参数放入提示词

## 7. 最终提示词模板

```
Objective: [一个可观察的结果、受众、渠道和主要验收标准。]
Reference binding:
- [Image 1]: 身份/产品权威；保留 [...]。
- [Image 2]: 环境/几何权威；保留 [...]。
- [Video 1]: 运动/镜头/节奏权威；不继承 [...]。
- [Audio 1]: [精确复用 / 音色 / 节奏 / 音乐] 权威。
- [Storyboard 1]: 镜头顺序和构图权威。
Immutable locks: [身份、SKU、几何、精确文案、对白、证据、版权、终态。]
Target duration: [确认时长。]
Timeline:
【0:00-0:03】[开场状态、钩子/触发、主体动作、镜头、同步音频、锁定。]
【0:03-0:08】[主要动作、接触或证明、可见结果、镜头/剪辑、音频。]
【0:08-0:12】[反应、升级、对比或转场；连续性。]
【0:12-0:15】[回报、精确文案/CTA 或终态、稳定并停留。]
Visual direction: [制作风格、光线、调色、质感、氛围（仅当未被来源拥有时）。]
Audio direction: [对白、语音、环境音、物理效果、画内音乐、观众专属配乐、沉默。]
Preserve: [高成本重做不变量的正向列表。]
Avoid: [高成本失败的短列表。]
```

## 8. 输出契约

返回 7 项内容：

1. **Creative intent** — 创意意图和主要验收标准
2. **Confirmed setup** — 时长、目的地/画幅（如已知）、模式、锁定
3. **Reference Role Map** — 每个来源的确认顺序和权威
4. **Timeline** — 完整连续区间
5. **Final Seedance 2.5 prompt** — 一个精确提示词，非多个竞争草稿
6. **Review checklist** — 可观察的参考、连续性、真实性、交付检查
7. **Controlled retry** — 一个可变或局部区域以更改

直接生成时，将精确提示词和包交给运行时。诊断时，命名可见失败、可能原因、最小局部修复、保留列表和一个重试变量。

## 9. 质量基准

- 保护完整兼容的参考覆盖；使用角色和优先级让丰富的包可读，而非修剪所需视觉证据
- 明确参考权威、事件顺序和终态
- 当文字无法控制空间或时间问题时，使用故事板、分镜或动作来源
- 让产品、身份、文案、证据、版权、安全和几何保持来源所有
- 局部失败用局部修复；不要重新生成已通过序列
- 将生成概念与捕获的游戏玩法、真实 UI、验证事实、建筑真实、医疗指令或当前目的地条件分开
- 不要将第一方营销、社区流行度或单个预览转化为运行时或可重复性声明
