# 接口测试用例二次检查与评分规则

## 一、检查目标

对 AI 生成的接口测试用例进行二次检查，确认：

- 是否与契约一致
- 是否覆盖正向和异常
- 是否包含边界/等价类
- 是否缺少关键流程或状态流转
- 是否存在断言空泛、模板不规范、幻觉字段等问题

## 二、问题等级

### 严重

- 虚构契约中不存在的字段、状态码、返回结构、业务规则
- path、method、参数位置写错
- 鉴权规则与契约不一致
- 缺少正向主场景
- 断言不可执行或与预期矛盾

### 一般

- 缺少边界场景
- 缺少常见异常场景
- 状态流转覆盖不足
- 断言不够具体但仍可理解
- 场景命名不规范

### 提示

- 可增加更高价值的补充场景
- 可合并重复用例

## 三、评分维度

总分 100。

| 维度 | 分值 | 说明 |
| --- | --- | --- |
| 契约一致性 | 30 | path、headers、body、字段名、约束、鉴权、返回结构是否一致 |
| 参数覆盖完整性 | 20 | 必填、非必填、格式、长度、范围、枚举是否覆盖 |
| 场景覆盖完整性 | 20 | 正向、异常、边界/等价类是否覆盖 |
| 流程/状态覆盖 | 10 | 依赖链、审核、绑定、重复操作等是否覆盖 |
| 断言可执行性 | 15 | 断言是否具体、可执行、可观察 |
| 模板规范性 | 5 | 字段是否齐全、格式是否规范 |

## 四、扣分建议

- 幻觉字段/幻觉状态码/幻觉业务规则：每处 `-10`，计严重问题
- path 或 method 错误：每处 `-10`
- 参数位置错误：每处 `-8`
- 缺少正向主场景：每接口 `-8`
- 缺少关键异常场景：每接口 `-5`
- 缺少边界/等价类场景：每接口 `-4`
- 缺少状态流转关键场景：每接口 `-4`
- 断言模糊：每条 `-2`
- 模板列缺失或字段格式错误：每条 `-1`

## 五、最终结论

- `90-100`：优秀，可进入人工抽检
- `80-89`：可用，建议修少量问题
- `70-79`：一般，需补充后复审
- `<70`：不通过

额外规则：

- 只要存在任一严重问题，最终结论不得判定为“通过”
