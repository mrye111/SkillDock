## 修复记录（2026-09-08）：目标为符号链接/目录联接时的处理

**用户案例**：`~/.cursor/skills/product-designer` 是指向已清空的 `~/.agents/skills/product-designer` 的悬空符号链接。同步时 `exists()` 跟随链接把它误判为「目标缺席」→ 走新增流程 → rename 到悬空链接上被 Windows 拒绝（os error 5），界面误报「权限不足」。

修复（commit `fix: 目标为符号链接/目录联接时单项阻塞…`）：
- `digest_directory` / 备份快照改用 `symlink_metadata`（不跟随链接）：悬空与有效链接都能识别
- 链接目标 → 计划项 `blocked` + `unsupported` 状态 + 明确中文原因（「目标是符号链接/目录联接，按规则不跟随、不改动；请确认后手动处理」），不再拖垮整个预览/矩阵
- 与 §8.5 一致：不跟随、不覆盖、不删除链接；用户需手动处理
- 新增 2 个集成测试（悬空联接、有效联接），共 28 项集成测试全绿
